# Project Chronicle 前端 UI 风格与动效规范

- 日期：2026-10-07
- 依据：[产品文档](../PRODUCT_SPEC_AI_NARRATIVE_SLG.md)、[轻量化技术栈选型](../../技术方案/总体架构/2026-10-07-MVP轻量化技术栈选型.md)及本轮 UI 要求
- 适用范围：创作工作台、剧情图编辑器、游戏试玩与玩家运行时
- 状态：视觉方向已确定；首版创作首页、示例叙事图和技术环境弹窗已映射到前端代码，其余正式编辑页面尚未实现

## 1. 背景与目标

Project Chronicle 同时包含创作工具与叙事游戏体验：作者需要处理 Story Bible、人物、场景、分支、校验和构建；玩家需要沉浸于剧情、做出选择并观察路线后果。UI 既要承担复杂创作工作，也要呈现游戏的情绪和动态。

本规范将以下用户要求转成可执行的设计约束：

1. 适量使用动态效果，强化叙事和游戏感。
2. 使用有辨识度的加载动效，避免通用转圈动画。
3. 页面要有层次、质感和完整视觉体系，同时适配多种题材。
4. 所有界面图标使用 SVG；产品 UI 中不使用 Emoji。

## 2. 视觉定位

### 2.1 风格名称

**沉浸式叙事工作台（Cinematic Narrative Atelier）**

创作端呈现精致、专业、可长时间工作的叙事编辑空间；试玩与玩家端将同一套设计语言转为更有氛围感的游戏界面。使用克制的暗色画布、清晰的内容层级、局部光感和有方向的动效，让界面有游戏气息，但不妨碍阅读和编辑。

### 2.2 通用性规则

- 主界面不绑定奇幻、校园、科幻、恋爱或悬疑等具体题材，不使用固定世界观符号作为导航和操作图标。
- 创作工作台使用统一的中性 UI 外壳；试玩界面可读取项目的题材色彩、背景和字体主题。
- 颜色、图标、节点形态和状态提示均有语义，不单靠装饰辨认功能。
- 默认提供深色主题；浅色主题沿用同一套语义色和组件规范。
- 项目可设置强调色，但不能覆盖成功、警告、错误等系统语义色。

## 3. 色彩与材质

### 3.1 默认深色主题

| Token | 色值 | 用途 |
|---|---|---|
| `--canvas` | `#0B1020` | 主背景、剧情画布 |
| `--surface` | `#111A2B` | 导航、侧栏、基础面板 |
| `--surface-raised` | `#18243A` | 浮层、卡片、选中面板 |
| `--surface-hover` | `#202E46` | 悬停和次级交互区域 |
| `--border` | `#2B3951` | 面板边界、分隔线 |
| `--text-primary` | `#F1F4FA` | 标题和正文 |
| `--text-secondary` | `#B4C0D2` | 次级信息、描述 |
| `--text-muted` | `#8391A8` | 时间、辅助标签、占位内容 |
| `--accent` | `#72DDC9` | 主要操作、当前路线和焦点 |
| `--accent-warm` | `#E6B477` | 重要节点、剧情提示和少量强调 |
| `--accent-violet` | `#A79BFF` | AI 生成、灵感或候选内容标记 |

语义色单独管理：成功 `#69D39A`、警告 `#F2C56F`、错误 `#FF7785`、信息 `#76BDF0`。状态标签同时使用 SVG 图标和文字，避免只靠颜色传达状态。

### 3.2 浅色主题

浅色主题使用暖灰白画布 `#F3F5F8`、白色面板 `#FFFFFF`、浅灰分层面 `#E9EDF3`、深色正文 `#1C2534`。强调色使用深一档的青绿色以保证文字和控件对比度。浅色主题不能通过简单反色生成，需分别检查输入框、画布节点、悬浮层和禁用状态。

### 3.3 背景与材质

- 主背景允许低透明度的径向光晕、细网格或极淡噪点，营造空间层次。
- 光效集中于当前选中节点、主要 CTA、生成进度和路线高亮区域。
- 面板以纯色分层、细边框和柔和阴影建立深度；避免所有卡片都使用大面积渐变和强发光。
- 正文区域保持稳定底色和足够对比度，不把复杂纹理铺在长文本底下。

## 4. 字体、间距与形状

### 4.1 字体

- 中文与拉丁文字：`Inter, "Microsoft YaHei UI", "PingFang SC", "Noto Sans SC", system-ui, sans-serif`，按设备已有字体回退，不依赖联网字体才能正确显示。
- 标题通过字号、字重和留白形成层级；主要页面标题建议 24–32 px，区块标题 18–22 px，正文 14–16 px，辅助信息 12–13 px。
- Flag、变量、模型名、文件 ID 和调试数据使用等宽字体：`ui-monospace, "Cascadia Code", Consolas, monospace`。
- 正文行高建议 1.5–1.7；剧情试玩正文优先保证舒适阅读宽度。

### 4.2 间距与圆角

- 使用 4 px 基础间距单位，常用步长为 4、8、12、16、24、32、48 px。
- 控件圆角 8 px，卡片和面板 12 px，弹窗 16 px；避免每个元素都使用胶囊形圆角。
- 边框保持细而清楚；阴影用于建立浮层层级，不用于装饰每个控件。

## 5. 页面布局与信息层级

### 5.1 创作工作台

桌面端采用稳定的编辑器布局：

- 左侧主导航：项目、Story Bible、角色、剧情、构建、设置等主要模块。
- 顶部工作栏：当前项目、章节或 Scene、保存状态、撤销/重做、试玩和构建操作。
- 中央工作区：图编辑画布、文本编辑器、角色列表或验证结果。
- 右侧检查器：当前节点、角色或条件的详细属性与操作。
- 按页面需要使用可收起的辅助面板；不要为了保持三栏而压缩正文和画布。

剧情图页面优先展示中心画布与路径关系；Story Bible、人物和 Scene 编辑页优先展示正文与结构化属性；验证页突出错误、受影响节点和修复入口。

### 5.2 游戏试玩与玩家端

- 试玩时提供进入沉浸模式的明确入口，可收起创作工具栏和调试面板。
- 对话、旁白、角色名和选择项建立稳定层级；选项呈现为可感知的决策控件，而不是普通文本链接。
- 手机、论坛、地图、物品、人物关系等系统采用一致的卡片、标签和导航语言，并可按项目题材更换内容皮肤。
- 路线图、结局图鉴和收藏状态可使用 SVG 图形和数据可视化呈现，避免复杂信息只写在长列表里。

### 5.3 响应式规则

- 创作图编辑器以桌面宽屏为主要工作环境；窄屏时将左右检查器改为抽屉或分步面板。
- 玩家阅读和选择流程适配窄屏，避免横向滚动。
- 屏幕空间不足时优先保留正文、当前选择和核心导航；低频调试信息折叠显示。

## 6. 组件风格

- **主要按钮**：清晰的主次层级，主操作使用强调色填充，次操作使用描边或中性底色；所有按钮必须有文字或可访问名称。
- **卡片**：使用标题、摘要、状态和主要操作构成信息层级；选中卡片增加边界与轻微光效。
- **剧情节点**：通过标题、节点类型标签、状态 SVG 和边框区分 Scene、Choice、Gate、Ending 与校验错误；当前路线使用强调色描边和路径高亮。
- **输入控件**：焦点状态明显；错误、禁用、生成中状态均显示明确文案。
- **空状态**：用简洁 SVG 场景图、下一步说明和一个主要操作构成，不使用 Emoji 或无意义的插画占位。
- **反馈提示**：Toast 只承载短反馈；涉及长任务、失败详情或修复建议时放入任务面板或验证结果区。
- **生成任务**：展示当前阶段、完成状态、可确认的进度和取消操作；不编造模型调用进度。

## 7. 动效规范

### 7.1 动效原则

动效用于说明状态变化、引导视线和传达剧情节奏。每个动效必须对应一个明确的界面事件，例如选择节点、路径变化、章节进入或任务阶段更新。

### 7.2 推荐时长

| 动效类型 | 建议时长 |
|---|---:|
| 按钮、标签、焦点反馈 | 120–180 ms |
| 卡片、菜单、面板展开 | 180–280 ms |
| 路径强调、节点进入 | 240–420 ms |
| 试玩场景切换 | 350–650 ms |

优先使用 `opacity`、`transform` 和 SVG `stroke-dashoffset`；遵循统一的缓入缓出曲线。避免高频抖动、闪烁、持续呼吸和大面积视差。

### 7.3 适用于本产品的动态效果

- **剧情路径**：选中 Choice 后沿连接线短暂描亮，后续相关 Scene 节点依次高亮。
- **生成变化**：新建 Scene 或角色卡片轻微淡入和上浮；批量创建时错开少量时间，避免整屏同时弹跳。
- **试玩转场**：切换 Scene 时让正文和背景分层淡入，背景只做轻微位移或色调变化。
- **状态反馈**：Flag、属性或任务状态变化时短暂强调相关标签，并显示数值或状态变化。
- **工作台氛围**：背景网格和局部光感保持静态或低频变化，不让整个画面持续运动。

## 8. 新颖加载动画：叙事脉络编织

### 8.1 视觉概念

以一条 SVG 叙事线逐步连接 Scene 节点，形成从创意输入到可玩路线的“脉络编织”动画。线路被绘制、节点逐个亮起，当前处理阶段由一个活动节点表示。它与剧情图、生成任务和路线校验直接相关，避免套用通用圆形转圈。

### 8.2 动画序列

1. 显示极淡的画布网格和尚未连接的节点轮廓。
2. 当前阶段节点以强调色描边出现。
3. SVG 曲线沿实际路线方向绘制，连接下一个 Scene 节点。
4. 已完成节点转为稳定状态，活动节点继续轻微高亮。
5. 完成时整条路线短暂统一点亮，随后切换到结果界面。

### 8.3 状态文案

按真实任务阶段显示文本，例如：

- 正在解析故事设定
- 正在整理人物关系
- 正在生成剧情节点
- 正在检查路线条件
- 正在准备试玩版本

若任务返回可靠进度，显示真实百分比或阶段数；若只有阶段状态，显示当前阶段和已完成步骤，不显示虚构的进度数值。长时间任务应提供任务说明和取消入口。

### 8.4 实现约束

- 动画由 SVG 路径、节点和 CSS transition/keyframes 实现；首版不需要 3D 或粒子引擎。
- 动画必须可以重复播放，但在同一页面保持克制；无任务时静止。
- 用户启用减少动态效果时，改为短淡入和静态阶段状态。
- 错误发生时停止路线推进，定位失败阶段并显示文本说明；错误不能只用红色闪烁表示。

## 9. SVG 图标与 Emoji 规则

### 9.1 硬性要求

- 产品 UI 中不使用 Emoji 充当图标、按钮符号、状态标识、空状态插画或加载元素。
- 导航、按钮、状态、提示、菜单、图表装饰和应用标识均使用统一风格的 SVG 图标或 SVG 插画。
- 图标优先统一使用 SVG 图标集，例如 `lucide-react`；需要品牌或剧情专属符号时绘制配套 SVG。
- SVG 图标统一使用 16、20 或 24 px 画布，默认描边宽度约 1.75–2 px，端点和转角风格一致。
- 装饰性 SVG 标记为 `aria-hidden="true"`；独立操作图标必须有可访问名称和键盘焦点状态。
- 用户输入或导入的剧情正文按内容本身展示；Emoji 不作为产品控件或界面装饰使用。

### 9.2 资产风格

- 使用几何清楚、轮廓简洁、易辨认的线性图标；选中或警告状态可使用少量实心填充。
- 保持图标表达一致，例如“锁定”始终代表条件不可用，“分支”始终代表剧情路径。
- SVG 颜色继承 CSS `currentColor` 或设计 Token，避免为同一个图标维护多套硬编码色值。

## 10. 可访问性与性能

- 所有操作可通过键盘到达并有清晰焦点；节点画布提供键盘选择和可读的节点信息。
- 颜色之外必须有文字、形状、线型或图标表达状态；保证正文、控件和状态文字具有足够对比度。
- 支持 `prefers-reduced-motion`；减少动态模式关闭路径流动、视差、连续脉冲和较长转场。
- 动效不拦截输入、不延迟保存、不阻塞取消操作；加载状态始终显示可读文本。
- 大型图谱只对当前视口和当前状态做动画，避免所有节点同时重复运动。

## 11. 禁用的视觉做法

- 禁止使用 Emoji 代替 SVG 图标。
- 禁止把所有页面做成无层级的简单表格或默认后台模板。
- 禁止每个卡片都发光、每个按钮都渐变或每个状态都播放动画。
- 禁止把题材限定在固定幻想符号、科幻 HUD 或单一游戏类型的装饰中。
- 禁止用持续旋转的默认 Spinner 作为主要加载表达。
- 禁止用闪烁、强烈缩放和无节制粒子覆盖长时间阅读区域。
- 禁止使用假的进度百分比或只靠动画隐藏任务停滞。

## 12. 首版落地顺序

1. 建立颜色、字体、间距、边框、阴影和状态 Token。
2. 实现主导航、顶部工作栏、面板、按钮、输入框、标签和 Toast。
3. 将 SVG 图标统一封装，并在代码检查中禁止新增 Emoji 图标。
4. 实现剧情图节点与选中/路径高亮动效。
5. 实现“叙事脉络编织”加载组件，并绑定真实任务阶段。
6. 在试玩模式补充 Scene 转场、对话和 Choice 的交互动效。
7. 完成深色主题后再补浅色主题和窄屏规则。

## 13. 验收清单

- [ ] 创作工作台有统一的深色视觉语言、明确层级和可持续阅读的正文区域。
- [ ] 剧情图可区分节点类型、当前选择路径和校验错误。
- [ ] 页面动效都能对应到具体交互或叙事状态，不造成持续干扰。
- [ ] 加载动画使用 SVG 叙事路径和节点，显示真实阶段及真实进度。
- [ ] 全部产品图标和装饰图形使用 SVG，界面 UI 不含 Emoji。
- [ ] 键盘焦点、颜色对比和减少动态偏好有明确处理。
- [ ] 创作外壳保持题材通用，试玩界面可以按项目主题调整。

## 14. 最终风格定义

Project Chronicle 的前端采用**沉浸式叙事工作台**：以深色中性画布和精致分层建立专业感，以局部青绿色与暖金强调关键路径，以 SVG 节点编织动效表现 AI 创作和剧情推进。创作工具保持清晰稳定，试玩体验增加转场与情绪反馈；统一设计 Token 支持不同游戏题材，所有 UI 图标使用 SVG，禁止 Emoji。

## 15. 首版页面落地

首版脚手架已将视觉规范应用于 `src/client/App.tsx`、`src/client/components/NarrativePreview.tsx` 和 `src/client/styles.css`：

- 首页采用深色叙事工作台结构，展示创作空间、剧情图示例和本机技术基底。
- 剧情图示例使用 React Flow 展示场景、分支和结局节点；明确标注为示例路线，不代表已创建项目数据。
- “检查技术栈与环境”按钮打开原生可访问弹窗，检查中使用 SVG 路径逐点编织的动效；支持键盘关闭和 `prefers-reduced-motion`。
- 页面图标使用 Lucide SVG 和内联 SVG，不加载在线字体或图片，不以 Emoji 作为界面符号。
- 页面显示项目数据本地保存，同时明确提示远程 AI 请求会发送至用户配置的服务。

当前页面属于脚手架首页，不包含产品文档中完整的 Story Bible、人物、Scene、校验、构建或玩家流程。由于依赖安装/前端构建是否可用取决于本机 npm registry 连通性，视觉效果仍需在构建成功后做浏览器实测。
